# Состояние реализации и журнал проверок

Этот документ содержит факты о рабочем дереве и проверках. Проектные решения
находятся в [architecture.md](architecture.md), протокол измерений —
в [hardware-bringup.md](hardware-bringup.md).

## Текущее состояние

Ветка `rewrite/nimbus-v2`. Есть новая точка входа, конфигурация ESP-IDF 5.5.3,
разделы и первая часть board: безопасные GPIO, ADC oneshot/eFuse calibration,
уровни кнопок, подготовка reset/deep-sleep. `app`, `ui`, `sensing`, `power`,
`storage`, ISR/pending кнопок и распознавание жестов ещё не реализованы.
На COM3 записан диагностический режим этапа 1; v1 на плате заменена.
Это не работающий монитор качества воздуха: экран тёмный, BSEC не запускается.

## Исходное состояние v1

- `master` сохранён на `d234ecc`.
- Локальные правки и неотслеживаемые файлы v1 сохранены в stash
  `ccb941116f547c6bd0c7033db7c4066efd0e800c` с сообщением
  `backup: v1 local changes before clean Nimbus v2 foundation`.
- Старые `build/`, `managed_components/`, `.cache/`, `sdkconfig` и lock-файл
  сохранены вне проекта в локальной резервной папке.
- Для восстановления stash следует использовать отдельное рабочее дерево v1,
  а не накладывать его на v2.

## Проверка устройства до очистки

COM3 открыт на 115200 бод, без команды намеренного сброса или прошивки.
Получена строка работающей прошивки:

```text
sensor_runtime: IAQ=109 STATIC_IAQ=137 phase=WARMUP acc=0 valid=no stab=yes run_in=no mode=LP
```

Инкрементальная сборка v1 завершилась без предупреждений. Это подтверждает
доступ к UART и телеметрию v1, но не завершение прогрева и не точность показаний.

## Проверка чистой основы, коммит ad2dcfd

- В собственных исходниках остался только новый `main/app_main.c`.
- Старые компоненты, submodules и `.gitmodules` удалены.
- Все 38 готовых ассетов совпали с исходными SHA-256; содержимое `assets/`
  также совпало с `master`.
- Сборка с новым `build/` и `sdkconfig` завершилась без предупреждений;
  `nimbus.bin` имел размер `0x25a30` байт. Это размер до включения coredump.
- Компиляция в песочнице сначала не нашла Ninja и получила ошибку владельца SDK;
  проверка выполнена вне песочницы, без изменения глобального Git config.

## Уточнение архитектуры перед этапом 1

Проектные изменения: UI владеет дисплеем; handles передаются через composition;
добавлены навигация, фазы BSEC, light/deep-sleep и протокол начальных измерений.
В конфигурацию добавлены coredump ELF/CRC32 на flash и panic по Task WDT.
`espcoredump` явно добавлен в зависимости минимальной сборки: одного раздела CSV
и defaults без компонента было бы недостаточно.

- `idf.py build` завершилась без предупреждений компилятора и CMake.
- Сгенерированная таблица: `coredump` по 0x310000, размер 0x10000, конец 0x320000
  укладывается во flash 4 МБ; существующие offsets app/storage сохранены.
- В сгенерированном sdkconfig проверены flash/ELF/CRC32, максимум 8 задач,
  отдельный стек 2048 байт, WDT panic и timeout 10 с.
- `nimbus.bin` после изменений — 172016 байт (`0x29ff0`).
- Предыдущий локальный sdkconfig сохранён в `.cache/` перед генерацией нового.
- `Sun.jpg` обнаружен в источнике ресурсов; теперь там 38 изображений и два OTF.
  Готовые файлы `assets/` не изменялись.

Никаких фактических значений ADC или тока сна пока нет. Все поля протокола
измерений остаются незаполненными. Физические отключения батареи, измерение тока
и контролируемая паника не выполнялись.

## Повторное уточнение отказов и запуска

Специфицированы стартовый контроль питания до панели/подсветки, безопасный режим
после трёх panic/WDT и сброс crash_count после пяти минут штатной работы.
Подтверждённое выключение больше не отменяется из-за отсутствующего ACK sensing;
для headless FAULT заданы long PREV и автоматический сон через 120 с.
Разделены сырые события board и жесты app; уточнены DIM, STARTING, ошибки OFF,
передача GPIO4, таймаут диалога и объединение пробуждений для замера батареи.
AGENTS.md сокращён до инвариантов и ссылок. Это изменения контрактов будущего кода,
а не реализованные драйверы или политики. Для этапа 3 выбран обязательный локальный
BSEC с ошибкой конфигурации при отсутствии пакета; соответствующий CMake будет
добавлен вместе с sensing.

- Лимит `CONFIG_ESP_COREDUMP_MAX_TASKS_NUM` увеличен до 16 в defaults и локальном
  сгенерированном sdkconfig; значение подтверждено также в build/config/sdkconfig.h.
- `idf.py build` завершилась успешно, без предупреждений компилятора/CMake;
  лог — `.cache/architecture-followup-build.log`.
- `nimbus.bin` — 172016 байт (`0x29ff0`); раздел coredump остаётся 64 КиБ.
- Для будущих задач задан бюджет стеков/TCB и ELF metadata. Полнота и вместимость
  их реального дампа пока не подтверждены: app/sensing/LVGL ещё не созданы.
- Прошивка, вызов panic, измерения разряженной батареи и проверка safe mode
  на устройстве не выполнялись. Рабочая прошивка на плате не менялась.

## Уточнения перед началом board, коммит 0944cd1

Перед началом board уточнены аварийный сон через RTC GPIO4 и reset GPIO23 без
вмешательства в DMA, два pending-слота кнопок вместо очереди фронтов, три вспышки
safe mode и ручной выход через RST/EN с явным очищением latch при POWERON.
Поведение физической RST/EN пока не проверено. В AGENTS.md убраны якоря заголовков;
ссылки ведут на документ, номера разделов указаны текстом.
Пользователь сообщил, что измерительного прибора нет: ток D1–D3 и независимое
напряжение батареи пока снять невозможно. Raw ADC и доступную заводскую калибровку
можно записать с платы; эти данные не подтверждают SOC или точность делителя.

## Этап 1: ADC, 19 октября 2026

Отдельная сборка `CONFIG_NIMBUS_BOARD_DIAGNOSTICS=y`, ESP-IDF 5.5.3, ESP32 revision
v3.1, USB от ПК; батарея подключена по описанию пользователя. Собрана и записана
на COM3, hash данных проверен esptool. Boot без abort/panic; ADC eFuse source=0
(Vref), 12 bit, attenuation 12 dB, 32 отсчёта, задержка установления 2 мс,
между отсчётами 1 мс. Независимого вольтметра нет.

| Серия A1 | raw min/median/max | ADC input mV min/median/max | Отсчёты на границе диапазона |
| --- | --- | --- | --- |
| GPIO14 LOW | 2734 / 2739 / 2745 | 2345 / 2349 / 2353 | 0 |
| GPIO14 HIGH | 2731 / 2739 / 2742 | 2342 / 2349 / 2351 | 0 |

Обе медианы равны 2349 мВ. При условном делителе ×2 получается 4698 мВ; это
не подтверждённое напряжение аккумулятора и не SOC. В данном подключении USB
положения GPIO14 не различаются по медиане. Без A2/A3 нельзя подтвердить наличие
батареи по ADC, коэффициент делителя и отключение измерительной цепи GPIO14.
Пользователь решил сейчас не отключать аккумулятор: A2–A4 остаются открытыми.
Ток D1–D3 не измерен: прибора нет. 2 мс — ещё не подтверждённый оптимум установления.

Выявлено отличие платы от исходной спецификации: flash сообщает 16 МБ при рабочем
профиле 4 МБ. Загрузчик выдаёт `Detected size(16384k) larger than ... (4096k)`;
разметка и размер заголовка оставлены 4 МБ. Это известное предупреждение boot,
а не compiler warning; оно не скрыто изменением уровня логирования.

Сброс EN через RTS USB-моста дал `reset_reason=1` (POWERON), wake_cause=0,
`rtc_retained=no`, boots=1. Это наблюдение электрического EN-reset; физическая
кнопка RST/EN и выход из настоящего safe-mode latch ещё не проверены. Код latch
и трёх вспышек пока относится к следующей реализации, не к этому диагностическому коду.

Диагностическая сборка завершилась без предупреждений компилятора/CMake:
`nimbus.bin` — 213472 байта (`0x341e0`), SHA-256
`18c0dec2522c65ee1996a71c7ffcec775dfaa72e58180804728249242717f305`.
Пакет ELF/map/bin/config и boot/flash/build logs сохранён локально в
`.cache/hardware-stage1-20261019/`; исходный UART — `.cache/board-boot.log`.
Настройка по умолчанию остаётся без диагностики; она включается overlay
`sdkconfig.bringup` и собирается в `.cache/build-board`.

Обычная сборка `idf.py build` с выключенной диагностикой также завершилась без
предупреждений компилятора/CMake; образ 172048 байт (`0x2a010`). Она не записывалась
поверх диагностической. После добавления нового компонента requirements main
указаны без Kconfig-условия: ESP-IDF собирает список зависимостей до загрузки Kconfig.

## Этап 1: запрос deep-sleep и wake

По UART отправлена `sleep`: GPIO4/14 RTC LOW, GPIO23 hold HIGH после аппаратного
reset панели, wake mask=3, таймер не включён. Пользователь нажал NEXT.
Получен полноценный boot с `DEEPSLEEP_RESET`, `reset_reason=8`, `wake_cause=3`
(EXT1 на единственном GPIO35), `rtc_retained=yes`, boots=2. После wake повторно
прошли GPIO/ADC init и обе серии чтения без abort. Это подтверждает deep-sleep
и пробуждение NEXT, но не ток, электрические уровни hold или потребление панели.
Лог — `.cache/board-sleep-next-wake.log`.

Повторная `sleep` и отдельное нажатие PREV также дали `DEEPSLEEP_RESET`,
`reset_reason=8`, `wake_cause=2` (EXT0 GPIO0), `rtc_retained=yes`, boots=3.
Первый короткий захват закончился до нажатия; boot записан продолженным захватом
в `.cache/board-prev-wake-continued.log`. Программный reset между сном и PREV
не выполнялся. Затем UART-команда `buttons` дала pressed_mask=0: перед дальнейшей
прошивкой обе кнопки отпущены.

Тем самым проверены оба источника пробуждения по отдельности, сохранность marker
между deep-sleep и повторный доступ к ADC. Открыты ток, сравнение reset/SLPIN,
удерживаемые кнопки, электрические уровни пинов, видимость 5% PWM и дребезг.
Повторяющиеся калиброванные медианы после wake были 2341–2347 мВ при USB;
никакого вывода о SOC из них не сделано.

Финальный исходник увеличивает reset-cancel ожидание на один tick, чтобы минимум
120 мс соблюдался и при вызове рядом с границей tick. Обе конфигурации пересобраны
без compiler/CMake warnings. Эта сборка повторно записана на COM3, boot снова
без abort; медианы ADC на контрольном старте — 2339 мВ LOW и 2341 мВ HIGH.
Размер диагностического образа остался 213472 байта; его SHA-256:
`fa959371e4aefd477e84373c97f853cd2cc149197fe34c9947c566b06a799143`.
Повторно выполнены команда terminal sleep и EN-reset через RTS; возвращение к
диагностике не считается кнопочным wake. Первые два кнопочных wake выше относятся
к предыдущему образу, отличавшемуся только длительностью этой паузы.
Финальные ELF/map/bin/config/logs — `.cache/hardware-stage1-20261019/final/`.
После EN-reset плата оставлена в диагностике, ожидающей UART-команды.

## Историческая команда запуска минимальной основы

```powershell
. .\activate.ps1
idf.py -p COM3 flash monitor
```

До начала board эта команда заменяла v1 минимальной основой без UI и измерений.
Тогда ожидались следующие строки (сейчас третье сообщение точки входа изменено):

```text
nimbus: Nimbus v2: clean firmware foundation
nimbus: ESP-IDF v5.5.3
nimbus: Board drivers, UI and application services are not implemented yet
```

Нужен полный boot log без aborts. Эти строки не проверяют будущие драйверы.
Порт COM3 относится к текущему подключению и проверяется заново при смене ПК.
