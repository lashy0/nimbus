- Пользователь добавил `Sun.jpg` для экрана яркости. При импорте/конвертации
  сопоставить ему нормализованный идентификатор `sun` с учётом регистра имени.

`../Nimbus-assets` служит источником для подготовки новых ресурсов, но текущая
сборка не зависит от наличия соседнего каталога. До добавления конвертации
нужные оригиналы будут скопированы в `artwork/` внутри репозитория, с отдельным
соответствием исходного имени и идентификатора ресурса. Этот импорт ещё не выполнен.
Соседняя папка пользователя остаётся исходным архивом и не изменяется инструментами
сборки.

## Подготовленные ресурсы прошивки

Из версии v1 сохранены только готовые ресурсы интерфейса: 5 бинарных шрифтов
и 33 изображения. Все 38 файлов остаются без изменений; собственный C/C++ код,
таблицы координат, загрузчики шрифтов и экраны из v1 не переносятся.

Источник этих готовых файлов: дерево `assets/` предыдущей реализации,
`master` на `d234ecc`. Для новой графики и повторной конвертации используются
оригиналы из `../Nimbus-assets`, а не восстановление изображений из `.bin`.

| Каталог | Файлы / назначение |
| --- | --- |
| `assets/fonts/` | `sf_b_10.fnt`, `sf_sb_15.fnt`, `sf_sb_30.fnt`, `sf_sb_50.fnt`, `sf_sb_60.fnt` |
| `assets/img/batt/` | По четыре уровня батареи с зарядкой и без неё, 8 изображений |
| `assets/img/face/` | Состояния качества воздуха, температуры и влажности, 12 изображений |
| `assets/img/status/` | Статусы good/mid/bad/warn/crit, damp/dry, minus/nothing/plus, 10 изображений |
| `assets/img/misc/` | `base.bin`, `lightning_charge.bin`, `sun.bin`, 3 изображения |

Все эти ресурсы относятся к согласованным экранам: IAQ, температура, влажность,
яркость, батарея и выключение. При разработке UI координаты и привязки создаются
заново. Наличие картинки зарядки не означает, что аппаратное состояние зарядки
уже можно достоверно определить.

Бинарные ресурсы предназначены для LVGL 8.4.0, 16-битного цвета с соответствующим
порядком байтов. Шрифты будут загружаться из `.fnt` во время запуска. Будущие пути:
`S:/spiffs/fonts/...` и `S:/spiffs/img/...`.

Пока UI не реализован, ресурсы не включаются в образ SPIFFS и не используются
минимальной точкой входа. В каталог `assets/` не добавляются документы, исходники
и артефакты сборки.

## Хранение и бюджет памяти

Принятый базовый вариант — SPIFFS и загрузка `.fnt` во время запуска.
EMBED_FILES для изображений и LittleFS остаются альтернативами для измерения
на этапе 2; решение о смене хранения пока не принято.

Пять готовых шрифтов суммарно занимают 80752 байта файлов. `lv_font_load` в LVGL8
загружает данные в heap; размер файлов не равен гарантированному расходу кучи.
После каждого шрифта и создания draw buffers/экранов фиксируются свободная
память, minimum free и largest block, отдельно для DMA-capable памяти.

При пробе EMBED_FILES проверяются реальный LVGL8 bin header, выравнивание,
формат цвета и чтение из flash. SPI DMA по-прежнему может требовать внутренний
буфер; обещание «нет расхода RAM» к полному конвейеру отрисовки неприменимо.
LittleFS подключается явной закреплённой зависимостью и с собственной упаковкой;
сравниваются mount, первое/повторное рисование, RAM и поведение при ошибке ресурса.
