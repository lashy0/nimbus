# Nimbus

Портативный монитор качества воздуха на ESP32. Показывает оценку качества воздуха
(IAQ с адаптацией к разным условиям), температуру и влажность.

## Структура проекта

```text
nimbus/
├── firmware/          # Проект ESP-IDF
│   ├── main/          # Инициализация и соединение компонентов
│   ├── components/    # Компоненты прошивки
│   ├── assets/        # Готовые изображения и шрифты
│   └── third_party/   # Библиотеки Bosch
├── artwork/           # Оригиналы изображений и OTF-шрифты
├── simulator/         # Предпросмотр общего LVGL UI на ПК через SDL2
├── scripts/           # Скрипты разработки
└── docs/              # Документация
```

## Аппаратная часть

| Компонент | Описание |
| --- | --- |
| Плата | LILYGO T-Display на ESP32 |
| Flash | 16 МБ на используемой плате; разделы занимают первые 4 МБ |
| Экран | ST7789, 135×240 пикселей, вертикальная ориентация, регулируемая подсветка |
| Датчик | Bosch BME680: температура, влажность, давление и сопротивление газа; IAQ рассчитывает BSEC2 |
| Кнопки | Две встроенные кнопки PREV и NEXT под экраном |
| Аккумулятор | 1150 мА·ч, 3,7 В, подключён к штатному разъёму платы |

Подключения:

| Узел | GPIO |
| --- | --- |
| Экран, SPI | MOSI — 19, SCLK — 18, CS — 5, DC — 16, RST — 23 |
| Подсветка | 4 |
| BME680, I2C | SDA — 21, SCL — 22; питание 3,3 В, адрес 0x76 или 0x77 |
| PREV | 0, активный LOW |
| NEXT | 35, активный LOW, внешняя подтяжка на плате |
| Измерение батареи | 34 — ADC1, канал 6; 14 — ADC_EN |

MISO экрана не используется (`-1`): GPIO21 занят линией SDA датчика.

## Сборка и прошивка

### Подготовка

Для сборки нужен ESP-IDF v6.1. Версия IDF закреплена в манифестах компонентов.

После клонирования получите библиотеки Bosch:

```powershell
git submodule update --init
```

### Сборка

Откройте PowerShell в корне проекта и активируйте окружение ESP-IDF.

```powershell
. .\scripts\activate.ps1
idf.py -C firmware build
```

Скрипт активации выбирает установленную v6.1. Путь к `eim_idf.json` берётся из
параметра, локальной настройки `.cache/esp-idf.json` или `IDF_TOOLS_PATH`
(включая его подкаталог `tools`). Если окружение ещё не настроено, укажите файл
конфигурации EIM один раз:

```powershell
. .\scripts\activate.ps1 -IdfConfigPath 'C:\path\to\eim_idf.json'
```

После успешной активации путь сохраняется локально; последующие вызовы работают
без параметров. Локальная настройка не попадает в Git.

`scripts/format.ps1` активирует окружение самостоятельно и тоже принимает
`-IdfConfigPath`. Для проверки форматирования без изменения файлов:

```powershell
.\scripts\format.ps1 -Check
```

Готовые изображения и шрифты из `firmware/assets/` упаковываются в SPIFFS
и записываются вместе с прошивкой. Для сборки конвертеры ресурсов не нужны.

### Прошивка и мониторинг

Подключите плату по USB. Замените `<PORT>` на порт своей платы:

```powershell
idf.py -C firmware -p <PORT> flash monitor
```

Для просмотра лога без повторной прошивки:

```powershell
idf.py -C firmware -p <PORT> monitor
```

## Предпросмотр UI на ПК

Симулятор основан на [lv_port_pc_vscode, release/v9.5](https://github.com/lvgl/lv_port_pc_vscode/tree/release/v9.5).
Используются общие исходники `firmware/components/ui/view/` и ресурсы из
`firmware/assets/`. ESP-IDF и подключённая плата для запуска не нужны.

Из корня проекта в PowerShell:

```powershell
git submodule update --init --recursive
.\scripts\preview.ps1
```

В Zed: **Shift+Alt+T → Nimbus: preview → Enter**. Задача сохраняет файлы,
собирает симулятор и открывает его окно. **Alt+T** повторяет последнюю задачу.

Нужны CMake в `PATH` и MinGW с `gcc`, `g++`, `mingw32-make`. Скрипт ищет
компилятор в `PATH`, `C:\msys64\ucrt64\bin` и `C:\msys64\mingw64\bin`.
При первой конфигурации CMake находит SDL2 **2.32.10** или скачивает его
автоматически из исходников с проверкой SHA-256. LVGL **9.5.0** и FreeRTOS
подключаются только из submodules. Сборка и загруженный SDL2 находятся в
`.cache/preview/` (с FreeRTOS — `.cache/preview-freertos/`).

По умолчанию сборка использует **две параллельные задачи**. В Ninja также
ограничены компиляция (две задачи) и линковка (одна задача). Для изменения
лимита передайте `-Jobs`; неограниченный `--parallel` скрипт не использует.

Окно показывает экран 135×240, увеличенный вдвое (270×480) со сглаживанием. Клавиши
← / → заменяют PREV / NEXT с той же логикой коротких нажатий и удержаний:
листание страниц, яркость и подтверждение выключения. `R` перезапускает приложение,
`U` переключает USB, `E` — ошибку сенсора, `C` — калибровку IAQ.
На текущей странице ↑ / ↓ меняют значение на 1, с Shift — на 10.
PageUp / PageDown переключают состояния оформления, Home возвращает исходное
значение страницы. Выбранные значения сохраняются при листании и `R`.
Исходные демонстрационные измерения задаются в `simulator/main/src/preview.c`.
Для выхода закройте окно; после изменения UI повторите команду сборки.

Повторный запуск готового превью без конфигурации и сборки:

```powershell
.\scripts\preview.ps1 -RunOnly
```

Для сборки с FreeRTOS добавьте `-FreeRTOS`. Если исполняемого файла ещё нет,
скрипт предложит сначала собрать его обычной командой. Изменения исходников
появятся в превью после новой сборки.

```powershell
.\scripts\preview.ps1 -BuildOnly
.\scripts\preview.ps1 -FreeRTOS
.\scripts\preview.ps1 -Jobs 1
.\scripts\preview.ps1 -CompilerBin 'C:\msys64\mingw64\bin'
```

Симулятор использует общий UI и переходы `app` из прошивки, включая таймауты,
уведомление USB и пробуждение экрана. Снимков экрана и параметров программы нет.
Управление и настройка IDE — в [simulator/README.md](simulator/README.md).

Общий `view/` использует LVGL и стандартную библиотеку C; аппаратная часть
`ui/display/` продолжает использовать настоящие API ESP-IDF. Датчик, кнопки,
подсветку, сон и производительность платы проверяют на устройстве.

## Диагностика перезагрузок

При panic отдельно сохраняются регистры и стеки в `coredump`. Для расшифровки
нужен ELF той самой сборки; сохраняйте `firmware/build/nimbus.elf` и `nimbus.map`
перед пересборкой. С подключённой платой:

```powershell
. .\scripts\activate.ps1
idf.py -C firmware -p COM3 coredump-info
```

В ESP-IDF 6.1 core dump использует ELF и SHA-256; выбор CRC32 удалён.
Дампы от прошивки на 5.5.3 разбирайте с сохранённым ELF и окружением 5.5.3.

Brownout и пропадание питания могут оставить прежний дамп. При трёх panic,
watchdog или brownout сбросах за серию запусков устройство уходит в сон до нажатия
кнопки. После пяти минут стабильной работы счётчик серии обнуляется.
