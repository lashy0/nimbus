# Nimbus v2

Новая реализация с нуля под LILYGO T-Display, BME680 и аккумулятор 1150 мА·ч.
Ветка: `rewrite/nimbus-v2`.

Старые исходники и submodules удалены из этой ветки. Из предыдущей версии
сохранены готовые изображения и шрифты в `assets/`. Старый проект доступен
в истории `master`.

Оригиналы графики и шрифтов находятся в `../Nimbus-assets`: 38 изображений
JPG/PNG и два шрифта OTF. Подробнее об источниках и подготовленных файлах —
в [описании ассетов](docs/assets.md).

## Текущее состояние

Есть минимальная сборочная основа ESP-IDF 5.5.3 с новой точкой входа
`main/app_main.c`. Начат компонент `board`: безопасные GPIO, ADC и reset/deep-sleep.
Отдельный диагностический режим выводит ADC по UART и принимает команды сна;
порядок включения описан в [протоколе этапа 1](docs/hardware-bringup.md).
Приложение, UI, sensing, политика батареи и упаковка SPIFFS ещё не реализованы.
Раздел `storage` зарезервирован для будущих ресурсов интерфейса.
Добавлен раздел `coredump` 64 КиБ и включена запись ELF/CRC32 на flash.

## Сборка

Из корня проекта в PowerShell:

```powershell
. .\activate.ps1
idf.py build
```

Новая сборка не использует конфигурацию, исходники или артефакты сборки v1.
`dependencies.lock` хранится в Git; `sdkconfig` и `build/` генерируются локально.
Основа пока не требует BSEC. С этапа 3 пакет станет обязательным: отсутствие
валидного `NIMBUS_BSEC_ROOT` будет ошибкой конфигурации CMake, согласно
[контракту подключения](docs/bsec.md#подключение-и-лицензия).

## Устройство

- LILYGO T-Display: ESP32, ST7789 135×240, две кнопки.
- BME680: I2C, SDA GPIO21, SCL GPIO22, питание 3,3 В.
- Аккумулятор 103030: 1150 мА·ч, номинально 3,7 В, штатный разъём платы.
- В этой сессии устройство доступно на COM3; порт нужно проверять после смены
  компьютера или переподключения.

Просмотр работающей прошивки:

```powershell
idf.py -B .cache/build-board -p COM3 monitor
```

Выход: `Ctrl+]`. На COM3 уже записан диагностический режим этапа 1: старого UI
и измерений BSEC на плате сейчас нет, экран тёмный. Для его UART-команд используйте
монитор из `.cache/build-board`, как описано в протоколе. Обычная сборка `build/`
остаётся основой с выключенной диагностикой.
